# Canonical Roadmap

Initiative: Road to Real - Phase 0 to Phase 1 Operationalization  
Status: Founder directive translated into execution sequence

## 1) Objective

Build a durable, emotionally resonant writing instrument capable of sustaining 200 retained paying users.

## 2) Program Phases

- Phase 0 (3-5 days): Operationalization and execution lock
- Phase 1 (4-6 weeks): Observatory completion + trust infrastructure + retention loop

## 3) Milestones

### Phase 0 Milestones

M0.1 - Canonical roadmap approved
- includes milestones, dependencies, blockers, success criteria, kill criteria

M0.2 - Stack decisions locked
- frontend, auth, database, analytics, payments, deployment, telemetry posture

M0.3 - Observatory architecture freeze packet complete
- Season Wheel, Trace Field, Pulse, Drift Atlas
- emotional purpose, interaction grammar, sparse/heavy behavior, mobile constraints, performance expectations, data dependencies

M0.4 - Alpha definition packet complete
- target users, onboarding flow, activation event, retention event, interview cadence, emotional signal tracking

M0.5 - Founder go/no-go for Phase 1 execution

### Phase 1 Milestones

M1.1 - Season Wheel production-hardening complete
M1.2 - Trace Field v1 internal-to-alpha release-ready
M1.3 - Pulse v1 release-ready
M1.4 - Drift Atlas v1 release-ready
M1.5 - Accounts + persistence continuity ready for alpha
M1.6 - Trust/security baseline verified (RLS, export/delete, backup, telemetry minimum)
M1.7 - Prompt vitality lifecycle active
M1.8 - Retention measurement loop active with qualitative signal capture
M1.9 - 25-user alpha live and monitored

## 4) Dependencies

- Stack lock depends on Phase 0 technical feasibility alignment across Architecture + Safety.
- Observatory freeze depends on Observatory + Safety + Editorial alignment.
- Alpha definition depends on retention metrics schema and interview cadence ownership.
- Phase 1 observatory releases depend on stable persistence and trust infrastructure.
- Payments readiness depends on account/subscription state model integrity and trust posture clarity.

## 5) Critical Blockers

- unresolved stack decisions
- unresolved privacy/telemetry posture
- ambiguous observatory definitions causing implementation drift
- lack of clear activation/retention events
- inability to enforce anti-diagnostic doctrine in observatory language and behavior

## 6) Success Criteria

### Phase 0 Success

- all Phase 0 artifacts complete and founder-approved
- no unresolved blocker in stack, trust, or observatory scope
- Phase 1 execution order is explicit and owner-assigned

### Phase 1 Success

- all four observatories are operationally coherent and doctrine-safe
- accounts and persistence support multi-session continuity
- trust posture is verifiable and user-legible
- early retention signal meets trajectory toward:
  - 25 alpha users
  - 40%+ weekly retention
  - 3+ sessions/week among retained users
  - evidence of emotional attachment signals

## 7) Kill Criteria

Kill or pause workstream if any are true:
- feature does not increase meaningful return behavior
- observatory drifts into dashboard/analytics/productivity framing
- language crosses into therapy/diagnostic/identity inference
- trust posture weakens (excessive telemetry, unclear deletion/export, weak privacy boundaries)
- scope expansion occurs during infrastructure hardening
- implementation proceeds without doctrine fit, retention hypothesis, owner, QA expectations

## 8) Track Ownership Model

- Observatory track: Observatory + Editorial + Safety + QA
- Trust infrastructure track: Architecture + Safety + QA
- Prompt vitality track: Editorial + Research + QA
- Retention track: Research + Product operations + Founder synthesis
- Conductor: anti-entropy oversight, prune/escalate where leverage drops

## 9) Gate Model

Gate A (end Phase 0):
- GO only if stack lock, observatory freeze, alpha definition, and blocker map are complete

Gate B (mid Phase 1):
- GO only if observatories show doctrine-fit and retention signal integrity in alpha

Gate C (Phase 1 completion):
- GO only if trust + retention + continuity signals support paid conversion path
