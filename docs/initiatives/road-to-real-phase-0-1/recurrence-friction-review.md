# Recurrence Friction Review

Date: 2026-05-26

## Core Question

What blocks a user from wanting to return before recurrence becomes recognizable?

## Friction Themes

- Early subtlety can be misread as under-delivery.
- Users with coaching/productivity expectations seek directives, not observation.
- Sparse observatory states can feel emotionally "flat" if return framing was not internalized.

## High-Risk Moments

- First low-signal submit.
- Run 2 (can feel like no new layer yet).
- First observatory open with insufficient stable pattern.

## Mitigations In Place

- First-run language emphasizes accumulation over instant insight.
- Sparse states use "gathering" and "beginning" language, not failure language.
- First-five-run copy avoids diagnosis/performance framing.

## Founder-Led Mitigations (Ops)

- In recruitment and onboarding: explicitly name 3-5 run horizon.
- Ask users to complete five runs over at least two days.
- Follow-up prompt after run 2: "Did anything small start to repeat?"

## Measurement Signals To Watch

- onboarding completed without run save
- run saved without observatory revisit
- observatory revisit without return session over 7 days
- run_saved sync_status splits (server vs local fallback variants)
